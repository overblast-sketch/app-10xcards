# Raport mvp-check: app-10xcards (2026-09-07)

Przebieg oficjalnego prompta `mvp-check` z kursu 10xDevs (General Toolkit
M0L0) wykonany przez osobnego agenta ze świeżym kontekstem, wyłącznie na
podstawie repozytorium (HEAD `31fe7c0`, drzewo czyste). Sesja implementująca
nie brała udziału w ocenie.

**Typ projektu:** aplikacja webowa SSR, Astro 6 + React 19 + TypeScript,
Supabase (auth + Postgres z RLS), adapter AI (mock / OpenRouter), Cloudflare
Workers. Rdzeniowy element danych: `flashcards`; pomocnicze `generations`,
`flashcard_candidates`.

## 1. Checklist

### ✅ 1. CRUD actions

| Operacja | Dowód |
|---|---|
| Create | `POST /api/generations/:id/save` (`src/pages/api/generations/[id]/save.ts`) → `saveGeneration()` → RPC `public.save_generation` (`supabase/migrations/20260907090000_initial_schema.sql`), `insert into public.flashcards ... where state in ('accepted','edited')`. Ręczne tworzenie od zera to świadomy non-goal PRD; zapis kandydatów jest pełnoprawnym trwałym Create. |
| Read | `listFlashcards()` w `src/lib/services/generation.service.ts`, SSR w `src/pages/deck.astro`, render `src/components/deck/DeckList.tsx`. |
| Update | `PATCH /api/flashcards/:id` (`src/pages/api/flashcards/[id].ts`) → `updateFlashcard()` w `src/lib/services/flashcard.service.ts`; UI `DeckCard.save()`. Edycja zapisanej fiszki, nie edycja przed pierwszym zapisem. |
| Delete | `DELETE /api/flashcards/:id` → `deleteFlashcard()`; UI `DeckCard.remove()` z potwierdzeniem. |

Trwałość Update/Delete dowiedziona w `tests/e2e/deck-edit-delete.spec.ts` (asercje po `page.reload()`).

### ✅ 2. Business logic

- Bramka akceptacji: `applyDecisions`, `selectCardsToSave`, `summarizeDecisions`, `toSaveDecisions` w `src/lib/services/gate.ts`; ta sama reguła w PL/pgSQL `public.save_generation` (walidacja stanów, `for update`, odmowa ponownego zapisu, statystyki, jedna transakcja).
- Walidacja tekstu: `validateSourceText()` (1 000 - 10 000 code pointów).
- Integracja AI: `OpenRouterProvider` (prompt z ochroną przed injection, timeout, ponowienie, `parseJsonLoosely`, zod, `normalizeCandidates`).
- Orkiestracja: `createGeneration()` (draft → provider → kandydaci → `failed` z komunikatem przy błędzie).

### ✅ 4. Authentication tied to a user

Supabase Auth email + hasło (`src/pages/api/auth/{signup,signin,signout}.ts`, `src/lib/supabase.ts`); `src/middleware.ts` ustala `locals.user`, przekierowuje z `/generate` i `/deck`, zwraca 401 dla `/api/generations` i `/api/flashcards`; każdy handler API sprawdza sesję. Wszystkie tabele mają `user_id references auth.users` i RLS `auth.uid() = user_id` per operacja; RPC jest `security invoker`. Własność egzekwowana na warstwie danych i przetestowana (R3).
